# 学习内容可下发修改说明

> 日期：2026-10-18  
> 范围：在现有 `/admin` 后台增加学习内容管理，并让已安装的 App 可以拉取已发布内容。  
> 关联：[服务器后台管理设计.md](服务器后台管理设计.md)、[学习内容设计文档.md](学习内容设计文档.md)

## 1. 行为

内置 `assets/` 仍是默认来源。服务器没有发布、手机没网、下载失败或 JSON 无法使用时，App 继续用打包进去的课程、对话、专项练习、音标和音频。

服务器发布某一份内容后，App 下次打开会拉取这一份并优先使用。其余未发布的内容仍用内置文件。已经下载的覆盖会留在本机，没网时继续用这份缓存。

撤回发布后，清单不再包含该项。App 下次同步会删掉对应缓存，回到内置文件。

不改 Whisper 模型、界面音效和字体。不自动改仓库里的 `assets/`。课号和题目 id 仍是进度键，改 id 不会迁移已有进度。

## 2. 后台怎么用

仍用原来的管理口令打开 `http://<主机>:8787/admin`。未设置 `ADMIN_TOKEN` 时，`/admin` 不存在。页面下方新增「学习内容」。

1. 选择内容包，点「打开」。
2. 导入与现有文件同结构的 JSON，或在页面里改字段，点「保存草稿」。草稿不会下发给 App。
3. 点「发布」。结构不合法时不会发布，页面显示原因。
4. 点「撤回」后，App 回到该项的内置文件。

课程按单元、课、题修改标题、题干、句子、选项、答案、题型、连线、填空和语言。单元对话按单元改台词。专项练习按章节与题目改（包内优先 `chapters[]`；仅有顶层 `exercises` 的旧包仍可被 App 兼容为单章）。音标表和对话应用题按整份 JSON 编辑。

音频按单个文件上传，避免改一条发音就重下全部听力。路径只接受：

- `audio/listening/{题目id}.mp3`
- `audio/dialogues/{单元id}_{行号}.mp3`

先「上传为草稿」，再「发布该音频」。单个音频不超过 2MB。JSON 包不超过 8MB。

## 3. 可下发的内容包

| 内容包 | 覆盖的内置文件 |
|---|---|
| `course/zero` | `assets/courses/course_zero.json` |
| `course/beginner` | `assets/courses/course_beginner.json` |
| `course/intermediate` | `assets/courses/course_intermediate.json` |
| `course/chinese` | `assets/courses/course_chinese.json` |
| `course/sanskrit` | `assets/courses/course_sanskrit.json` |
| `dialogues/units` | `assets/dialogues/unit_dialogues.json` |
| `dialogues/application_tasks` | `assets/dialogues/application_tasks.json` |
| `practice/pronunciation` | `assets/practice/pronunciation.json` |
| `practice/vocabulary` | `assets/practice/vocabulary.json` |
| `practice/speaking` | `assets/practice/speaking.json` |
| `phonetics/en_ipa` | `assets/phonetics/en_ipa.json` |
| `phonetics/en_zh` | `assets/phonetics/en_zh.json` |

课程 `id` 必须与包名一致，例如初级包的 `id` 必须是 `beginner`。专项练习的 `skill` 必须与包名一致。发布前按 App 现有模型检查字段：题型、题干、句子、答案、选项、连线和语言；若使用章节，检查 `chapters[].id/title/exercises` 非空且顺序正确（顺序即解锁顺序）。

服务器只保存管理员发布过的覆盖，不预装全部内置课程。清单为空时，App 与现在一样只用内置资源。

## 4. 接口

学员接口不需要登录，只返回已发布内容：

- `GET /v1/content/manifest`
- `GET /v1/content/packs/<kind>/<name>`
- `GET /v1/content/files/audio/<listening|dialogues>/<文件名>.mp3`

管理接口要 `Authorization: Bearer <ADMIN_TOKEN>`：

- `GET /admin/api/content/packs`
- `GET`、`PUT /admin/api/content/packs/<kind>/<name>`
- `POST .../publish`、`POST .../unpublish`
- `GET /admin/api/content/files`
- `PUT /admin/api/content/files/audio/<bucket>/<文件名>.mp3`
- `POST .../publish`、`POST .../unpublish`

`PUT` 只写草稿。发布把草稿复制为已发布版本，修订号加 1。再次发布再加 1。撤回清空已发布正文，修订号保留，草稿还在。

有 `DATABASE_URL` 时写入 Postgres 表 `content_documents`、`content_files`。没有数据库时用内存仓储，重启后丢失。

## 5. App

启动时向当前账号服务地址拉清单，最多等约 2 秒。已缓存且 sha256 一致的不重下。2 秒内没下完的留到下次打开。清单拉取失败时保留上次缓存，不挡住进课。

覆盖接入这些读取点：系统课程、专项练习、单元对话、对话应用题、音标表、听力 mp3、对话 mp3。听力仍是缓存文件优先，其次内置 mp3，再其次系统 TTS。

## 6. 改动位置

| 位置 | 作用 |
|---|---|
| `server/lib/content_repo.dart` | 草稿与已发布内容的内存、Postgres 仓储 |
| `server/lib/content_api.dart` | 公开清单、下载和管理接口 |
| `server/lib/content_validate.dart` | 发布前的结构校验 |
| `server/lib/admin_page.dart` | 后台「学习内容」区块 |
| `server/lib/api.dart`、`server/bin/server.dart` | 挂上内容仓储和路由 |
| `lib/data/sources/content_cache.dart` | 本机缓存和清单同步 |
| `lib/data/sources/course_loader.dart` 等加载点 | 有可用覆盖就用覆盖，否则用内置文件 |
| `server/test/content_api_test.dart` | 草稿不可见、发布、撤回、非法结构、音频字节 |
| `test/content_overlay_test.dart` | 有缓存、无缓存、坏 JSON、撤回后删除 |

## 7. 验收

1. 未发布时，`GET /v1/content/manifest` 的 `documents` 和 `files` 都是空数组。App 课程与改动前一致。
2. 导入一门课的 JSON，只保存草稿。清单仍为空，公开下载返回 404。
3. 发布后，清单出现该包和修订号。App 下次打开使用新标题或新题干；其他未发布课程仍是内置内容。
4. 故意去掉 `units` 再发布，接口返回 `invalid_content`，清单不变。
5. 撤回后，清单去掉该包。App 下次打开回到内置课程。
6. 上传并发布一条 `audio/listening/{题目id}.mp3`。该题播放新音频；其他题目仍用内置 mp3 或 TTS。撤回后回到内置音频。
7. 断网打开已下载过覆盖的 App，仍使用上次缓存。从未下载过的项使用内置文件。
