# 代码审查问题修复

日期：2026-10-24。

## 修复内容

- 后台进度表使用 DOM `textContent` 显示课号，已有恶意课号也不会执行脚本；同步接口拒绝非法课号和不能解析的进度字段。
- 在线账号只保存密码哈希，注册、登录、重设密码不再存储明文，后台也不再返回或展示明文密码。
- 本地账号绑定时直接迁移持久化槽位，保留源账号和目标更好的成绩。自动同步由应用根 widget 监听会话变化触发，解除认证与同步 provider 的循环依赖。
- 刷新请求核对会话版本和账号身份，退出或切换账号后丢弃旧响应。
- PostgreSQL 在同一条 UPSERT 中检查同步基准版本，并发冲突返回 409。
- 备份接受现有英语、中文和梵文课号。
- 数字拼音按完整音节标调，覆盖 `hao3`、`gui3`、`liu2`、`shui3`、`dou4`、`jiang3` 和 `ü/v` 输入。
- 专项题库生成检查忽略 Windows CRLF 与 LF 的差异。

## 服务端升级

新服务首次连接 PostgreSQL 时自动删除旧 `accounts.password_plain` 列，保留 `password_hash`，已有用户仍使用原密码登录。部署时停掉旧服务后启动新服务；旧服务代码仍引用该明文列，不能与新版本同时运行。

## 验证

客户端新增 `test/review_regression_test.dart`，覆盖真实 provider 的绑定迁移、备份往返、退出后的迟到刷新和拼音判题。

服务端新增 `server/test/security_regression_test.dart` 和 `server/test/postgres_regression_test.dart`。PostgreSQL 测试必须使用独立测试数据库，因为测试会模拟旧明文列的升级迁移；通过 `TEST_DATABASE_URL` 指定地址，在 `server/` 运行 `dart test`。未指定时跳过这两项数据库集成测试。

本机还通过浏览器验证恶意课号按字面显示、没有生成图片节点或执行事件处理器。
